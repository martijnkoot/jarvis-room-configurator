Run from repository root:

```sh
node --check dist/jarvis-room-configurator.js
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -v
CHROME_BIN='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
  SCREENSHOT_DIR=/tmp/jrc-workspace node tests/browser-check.cjs
```

The browser server serves only repository files on an ephemeral loopback port and
closes after validation. Browser fixtures simulate HA registry and state data;
only their recorder receives the test polygon service call. This is not real HA
runtime or hardware validation. Chrome covers both responsive viewports; Safari
covers the desktop fixture. Firefox, actual HA save/reload, mobile touch,
reverse-proxy URLs and authenticated
image hosting remain installation acceptance checks. No private upload API is
called. A URL's successful load now cannot prove future hosting availability.
Physical dimensions, image margins and registration must be checked by the user.
Ceiling/tilt projection, multiple floors and automatic room recognition remain
outside this change.
